# 面向 AI 协作的实现流程

这里采用“明确上下文 → 小任务 → 实现 → 实际验证 → 更新记录”的工作方式。
这是一套适合本项目的工程约定，不把 vibe coding 描述成有唯一标准目录格式的方法。

## 开始一个任务

1. 读取 AGENTS.md、P0 范围、当前里程碑和相关模块。
2. 选一个可独立验证的目标，用 [任务模板](tasks/TEMPLATE.md) 写清输入、输出和验收编号。
3. 先检查事实：当前代码、依赖版本、真实工具能力；不把旧教程或计划当成已实现事实。
4. 实现所需的最小变更。常规实现细节可以自行判断，不反复要求用户批准已授权的小步骤。
5. 遇到真正影响产品范围的选择再讨论；不要为了“更完整”引入新功能。

## 实现与验证

- 优先交付一个完整的小流程，不先铺大量没有行为的框架层。
- 给状态机、指标、确认门禁等规则写有价值的边界检查。
- UI Agent 的实际能力必须跑真实浏览器并保留证据，不能只跑 mock。
- 文档变更运行 pnpm check；功能实现后增加相应真实检查命令。
- 当前没有的 test/build/typecheck 不允许在总结里写通过。
- 改动多少、检查多大：不为文案或空目录写镜像式测试，不无限扩大无关检查。

## 收尾

- 写清实现、验证、已知限制和下一步。
- 更新 docs/plan.md 的真实进度，必要时更新 docs/decisions.md。
- 涉及状态或指标变更时同时更新 docs/execution.md、docs/acceptance.md。
- 服务启动/重启由用户执行；不自动推送、部署或发布。
- 下一次接手者从 README、AGENTS 和任务记录即可继续，不要求读完整聊天历史。

本次工作方式的外部参考见 [参考资料](references.md)，具体约定以本工程实际范围为准。
