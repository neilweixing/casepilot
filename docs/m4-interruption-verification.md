# M4 中断、历史与数据清理验证

日期：2026-10-30（Asia/Shanghai）。对应 [任务卡](tasks/M4-interruption.md) 与 D11、D12。本机可控样本验证已完成，完整 P0 尚未完成。

## 实现边界

操作发出前持久化 SENT，回执到达后继续正常步骤记录。关闭立即保存 INTERRUPTED，再等待浏览器收尾；尚无可靠回执的步骤保留 UNCERTAIN，未开始项保持 PENDING。已确定的结果和证据不被恢复器改写，不提供跨进程继续执行入口。

新锁包含运行 ID 与归属 PID。存活归属不被抢占；归属已退出但工具仍存活时阻止新任务；归属与历史匹配且相关进程全部退出后才回收残留锁。未知、旧格式或不匹配的锁不自动删除，需人工核实。

测试数据默认保留。明确清理样本仅操作本次独立合成记录，目标提供恢复入口，不永久删除用户数据。

## 方式

`pnpm lifecycle:check --scenario=<graceful|crash|cleanup>` 使用真实模型、Pi、Playwright MCP 和可见 Chrome，上传并确认独立生成的 xlsx。所有业务操作走 UI；目标计数接口只用于独立核对副作用。

每次使用 `data/lifecycle-check/<场景>-<检查 ID>/`，父进程持有全局浏览器锁。中断场景先完成只读用例，再执行创建用例，第三条保持待执行。验收层在原生点击成功且只读快照确认实际创建后暂存回执，生产执行器仍停在 SENT。随后正常关闭或终止这个自建子进程；没有关闭或重启用户服务。

重开原 SQLite，使用实际 API 注册与报告代码读取详情和 HTML，检查已完成结果逐字段一致、没有第三条开始事件、不能继续旧任务，等待后历史仍不变。API 使用内存请求注入，不冒称从管理页面发起了这次验收。测试侧只收尾自建子进程存活时记录的工具家族，生产恢复器不会杀死归属不明的进程。
