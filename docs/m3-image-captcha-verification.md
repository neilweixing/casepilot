# 普通图片验证码阶段验证

日期：2026-10-30（Asia/Shanghai）。对应 C04、C06、A05、E08。本机可控样本验证已完成，完整 P0 尚未完成。

## 本次实现

image 认证阶段新增 `captcha` 工具，分为 capture、submit、refresh。图像由真实 MCP 截取可见 img/canvas，限定 360×180 CSS 像素以内，拒绝整页、表单及与输入框重叠的区域。填写账号密码后仍只收录验证码区域，不通过整页截图发送凭证。

submit 只接受当前页面最新图片的 ID，图像必须实际进入模型请求，每张只提交一次；填写实际识别值后通过 UI 点击同一登录表单按钮。图片源或画布内容变化时旧图失效。刷新已提交图片前，必须有页面明确显示的验证码失败；未知登录结果不能靠刷新或换按钮重试。
已提交图像按实际图像来源/画布内容保留记录，导航后换证据 ID 也不能重用。下一次提交前要求旧验证码错误提示已清除，避免把残留提示当作新一次结果；不满足的页面需要适配。最终回归的模型请求另有 `captcha_image_sent` 标记，记录图像字节进入真实请求后才放行提交。

`CASEPILOT_CAPTCHA_ATTEMPTS` 默认 3，允许 1–5。识别和提交分别最多 N 次，刷新最多 N−1 次；导航、重新截图和刷新不重置累计预算。普通 UI 工具在 image 认证阶段只允许导航与快照，账号由 `fill_credentials` 填写；验证码填写、登录提交和刷新统一走专用工具。已发出的操作回执不可靠时仍按既有规则停止，不开放追加写入。

本阶段只支持 3–8 位普通英文字母/数字图片；看不清不能猜测，可有限刷新或说明认证无法完成。验证码失败暂停整批，后续业务不执行。滑块、点选、短信、扫码、第三方反机器人挑战不在本次范围。

## 验收方式

`pnpm captcha:check --scenario=normal|retry|exhaust|unreadable` 使用独立 SQLite、合成确认工作簿、真实模型/Pi/MCP/可见 Chrome。全局执行锁防止与用户任务重叠，服务由用户既有进程提供，不由验收命令启动或重启。

随机六位验证码通过图片资源显示，HTML、地址与计数响应不含答案。Agent 只能通过裁剪的真实图片识别；契约测试为核实目标本身，可读取合成 SVG 源码，但真实 Agent 验收不使用该方式。目标计数只独立核对副作用和识别结果，不代替 UI 操作。

正常/刷新恢复场景须真正进入受保护页面并完成步骤和预期。故障场景保留 PAUSED 快照，确认两条均未执行业务步骤，再由验收命令显式停止以释放资源，不自动继续或重跑。

正常与不可读样本使用本机 600 秒单用例配置；刷新恢复和持续拒绝专项使用 900 秒，避免慢模型的整条时限先覆盖验证码自身的次数上限。生产默认单用例时限没有因此修改。
