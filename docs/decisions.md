## 2. 实现建议与默认值

| 编号 | 建议 | 理由与验证要求 |
|---|---|---|
| T01 | Pi SDK + Playwright MCP | 复用模型工具循环和真实浏览器操作，M1 做真实接通验证 |
| T02 | TypeScript、pnpm、React、Fastify、SQLite | 单机工程的建议组合；M1 已安装 TypeScript/Fastify，React/SQLite 未安装，不冒称用户逐项指定 |
| T03 | 本机持久化历史 | 便于回查结果；中断不能丢失已经确认的用例结果 |
| T04 | 暂停、继续、停止 | 在受控边界处理，不承诺随时回滚正在进行的业务动作 |
| T05 | 中断不自动续跑 | 不能仅靠聊天会话恢复来判断提交动作是否安全重放 |
| T06 | 不额外自动清理业务数据 | 保留现场，按用例明确步骤处理清理 |
| T07 | 数值预算可配置 | 示例恢复/超时值未经过真实环境测定 |
| T08 | 同一环境任务独占浏览器状态 | 避免会话混用，案例间重新检查前置条件 |
| T09 | 文档与工程骨架先交付 | 业务功能状态保持未实现，不添加假成功 dev/test 命令 |
| T10 | M1 使用最小服务 + SDK 验收命令 | 服务仅提供可控页面；后续 M3 再接入完整任务 API，当前不提前实现管理界面 |
| T11 | M1 不加载磁盘扩展或 Skills | 采用官方 MCP 扩展和严格白名单；独立工作目录、配置、内存凭证与会话，不继承个人配置 |
| T12 | 用图像校验码验证图像能力 | 固定页面中的四位数字每次运行不同；截图实际发往模型且识别正确才通过，识别不可靠记 ERROR；不冒称真实验证码已验收 |
| T13 | 登录失效后按已开始的阶段决定继续位置 | 认证/输入校验阶段可显式继续并重试认证；准备或业务阶段保留 ERROR（已确认失败保留 FAILED），继续执行下一条，防止重复准备或提交。可控样本证据见 M4 验证记录 |
| T14 | 区分动作发出前的定位失败与发出后的不确定结果 | 前者可在次数/时间预算内取新快照恢复；后者保留 UNCERTAIN 步骤与 ERROR 用例，只读采集后收尾，不能因超时推断未提交，也不通过新目标或按键重放 |
| T15 | 中断先落盘，恢复只核实归属与读取历史 | 动作派发前持久化 SENT；退出时保存 INTERRUPTED 与未确认步骤，不自动续跑。只有匹配的旧锁及工具进程均确认退出才回收占用，存活归属和未知锁不被抢占 |
| T16 | 图片验证码只截取图像，认证重试有独立预算 | 最新图片必须实际进入模型请求，每张只提交一次；已提交图片只有明确验证码失败后才能刷新，累计识别/提交默认 3 次。该受控认证重试不放宽业务操作或不确定回执的重放约束；无法可靠完成时暂停整批 |

- 目标测试系统登录/验证码/前置准备的稳定性。
- 本机凭证存储实现和导出内容的脱敏。

这些属于后续实施验证，不是当前文档交付还需要反复询问的产品选择。
