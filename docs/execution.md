# 执行规则与指标

这是 P0 执行器和报告必须遵守的契约草案。规则变更同时更新 [验收清单](acceptance.md)。

## 1. 任务状态

| 状态 | 含义 |
|---|---|
| QUEUED | 已确认用例与环境，等待本机执行器 |
| RUNNING | 正在执行 |
| PAUSING | 已请求暂停，等待当前可控边界 |
| PAUSED | 不再发出新业务动作，保留执行现场 |
| STOPPING | 已请求停止，等待终止和收集证据 |
| COMPLETED | 本批已处理完，不代表所有用例通过 |
| CANCELLED | 用户停止，已有结果保留 |
| INTERRUPTED | 服务/进程退出导致中断，不自动恢复 |
| ERROR | 任务自身发生不可恢复的运行器故障 |

可继续的是 PAUSED，不是 CANCELLED 或 INTERRUPTED。
同一时间只允许一个任务持有浏览器。PAUSED 也占用当前执行槽，直到继续或停止，不启动另一任务抢占浏览器。

~~~mermaid
stateDiagram-v2
  [*] --> QUEUED
  QUEUED --> RUNNING
  QUEUED --> CANCELLED
  RUNNING --> PAUSING
  PAUSING --> PAUSED
  PAUSED --> RUNNING
  RUNNING --> STOPPING
  PAUSING --> STOPPING
  PAUSED --> STOPPING
  STOPPING --> CANCELLED
  RUNNING --> COMPLETED
  RUNNING --> ERROR
  RUNNING --> INTERRUPTED
  PAUSING --> INTERRUPTED
  PAUSED --> INTERRUPTED
  STOPPING --> INTERRUPTED
~~~

启动时扫描上一进程遗留的活动状态，标为 INTERRUPTED，并核实工具进程已终止/释放浏览器后才接新任务。
终止调用并不能自动证明服务器端的“创建/提交”未生效；记录最后确认动作与不确定状态，不自动重放。

## 2. 用例结果状态

| 状态 | 判断条件 | 是否加入通过率分母 |
|---|---|---|
| PENDING | 尚未开始 | 否 |
| RUNNING | 正在准备或验证 | 否 |
| PASSED | 全部确认的预期均被验证，证据齐全 | 是 |
| FAILED | 预期与实际明确不符，有可复查证据 | 是 |
| BLOCKED | 前置条件无法满足，或依赖缺失，不能开始有效验证 | 否 |
| ERROR | 模型/工具/定位失败、超时或证据不足，无法可靠下结论 | 否 |
| CANCELLED | 用户停止了尚未完成的用例 | 否 |
| INTERRUPTED | 程序中断，当前执行结果不确定 | 否 |

未开始项在停止后转为 CANCELLED；进程中断时当前用例记 INTERRUPTED，未开始项仍保留 PENDING，并在报告中标为未执行。
部分预期已验证但后续被停止/发生执行异常，整条不能记为 PASSED；保留逐项结果。
如果某项预期已明确失败，即使后续收集证据又出现工具异常，也保留 FAILED 及附加异常，不抹掉已确认失败。

## 3. 一条用例的阶段

VALIDATING → AUTHENTICATING → PREPARING → EXECUTING → VERIFYING → FINALIZING。

1. 校验来源版本、必要字段与可执行性。
2. 确保已处于所选环境并使用该环境的一组账号登录。
3. 检查前置条件。需要时通过 UI 准备，只能做用例目标明确涵盖的准备。
4. 按步骤实际操作网页，记录工具结果、页面变化、恢复尝试。
5. 对每项预期记录实际观察、结论和证据 ID。
6. 服务校验记录后写入最终状态，再运行下一条。

阶段与结果分开存储：PREPARING 失败与 EXECUTING 失败的含义不同。
无前置条件时可跳过准备，不能自行推断用户未要求的业务状态。
依赖上条用例产生的动态 ID 不作为 P0 默认能力；需要该数据时在当前用例的前置条件或步骤内明确准备。

## 4. 恢复与暂停

- 操作恢复：等待页面、重新取快照、修正定位，可有限尝试。
- 服务端在动作发出前检查目标；定位失败后必须重新取快照，再用最新目标恢复。每个准备阶段、操作步骤和独立预期默认最多 2 次恢复，恢复累计活动时间最多 120 秒；成功不清空累计次数，暂停不消耗时间，快照不能重置预算。达到任一上限后 ERROR，保留最初错误与恢复事件，不重跑用例。
- 业务重试：重新创建/提交/支付等动作可能有副作用，必须先检查上次是否已成功；不明时 ERROR，不盲点。
- 网页操作已发出、但没有可靠工具回执时，当前步骤标为 UNCERTAIN（结果不确定），用例为 ERROR；服务最多补采一轮只读快照/截图后收尾，不追加写入、重新导航或改用回车重放。只读现场可能无法补采，不能因此推断提交未生效。已确认 FAILED 仍保留。
- 派发网页操作前先持久化 SENT（等待操作结果）。进程关闭时立即保存中断状态，再等待工具收尾；重开历史时，已确认结果保留，活动用例为 INTERRUPTED，尚无回执的 SENT 步骤为 UNCERTAIN，未开始用例保留 PENDING。
- 新执行锁记录任务和归属进程。旧归属仍存活时不能改写其任务；旧归属已退出但工具仍存活时不能启动新任务。仅在锁、历史归属一致且相关进程均已退出后回收残留锁。旧格式、未知或不匹配的锁保持阻止，需人工核实，不能直接抢占。
- 查看历史或导出报告只读取已有结果，不自动续跑。测试数据默认保留；只有确认后的用例明确要求时才通过 UI 清理，并保留操作及结果证据。
- 整条用例自动重跑：禁用。用户重跑失败项时创建新 Run，保留原报告。
- 普通图片验证码：image 认证阶段只通过受控工具截取可见 img/canvas，确认图片实际发给模型后填写识别值并点击登录，每图只提交一次。默认最多 3 次识别/提交、2 次刷新，导航和刷新不重置累计预算；只有页面明确显示验证码失败后才可刷新已提交图片。未知回执仍停止，不通过登录按钮或回车绕过。看不清不猜测，无法可靠完成或耗尽预算时暂停整批，不开始业务步骤。真实成功率需要目标样本验证，不承诺任意图片可解。
- 整体环境不可访问或持续认证失败：暂停任务并说明原因，不将后续全部标为 FAILED。
- 普通业务在已登录后意外返回登录表单：暂停整批。已进入 PREPARING 或后续业务阶段的当前用例记 ERROR，已有明确失败保留 FAILED；显式继续从下一条开始，不重放准备或提交。仅 AUTHENTICATING/VALIDATING 阶段、尚未准备业务状态时，允许显式继续后重新认证当前条。
- 继续时读取同一环境、同一账号的最新凭证；地址或账号改变需要创建新任务。确认后的步骤/预期明确涉及登录、登出或密码功能时，预期登录页不按上述通用规则自动判为会话失效；具体流程仍需专项验证。
- 暂停在工具调用边界生效。超时或停止时需要终止可终止的调用，记录是否有未确认副作用。
- 用户在本机浏览器里人工修改页面后，继续前重新检查页面与前置条件，不使用旧元素引用盲目继续。

配置草案见 configs/runtime.example.json；当前通用执行通过 `.env` 控制定位恢复次数、120 秒恢复预算、验证码识别/提交次数和单用例时限。单用例默认 5 分钟、单任务 30 分钟；本机慢模型验收使用 10 分钟单用例，验证码恢复专项使用 15 分钟以区分次数上限。验证码次数由服务端限制，真实样本范围见专项验证记录。
这些数字没有经过用户目标系统测试，属于可调整的初值，不是性能承诺。

## 5. 通过判定与证据

证据最少关联 runId、caseId、stepId 或 expectationId、时间和来源。
优先保留实际工具成功/失败、页面观察和必要截图。每条失败用例有失败现场；通过用例保留关键预期证据。
通用执行关闭 Playwright MCP 动作附带快照的原生自动落盘；显式快照通过服务脱敏后保存，避免密码输入状态绕过脱敏进入 YAML 文件。截图仍需检查当前页面是否含凭证，不能以关闭文本落盘代替截图保护。
报告预览和下载使用同一渲染函数；归档文本与单项证据读取时再次脱敏，Cookie/Token 等敏感字段递归遮罩。报告只内嵌本次登记的证据，真实文件路径不能越出运行目录。缺少文件必须明确提示，不修改既有用例状态。
字段排列、样式、遮挡等视觉预期不能只凭页面文字存在就通过；需要相关位置/视觉证据。
“已点击”“看起来正常”只是一段文字，不能替代工具记录和逐项验证。
最终结构化输出缺失、无法关联到本次执行、没有证据或仍有未验证预期，都不得接受 PASSED。
报告中的失败分析区分事实与推测；无法确认根因时说明观察到的现象，不编造后端原因。

## 6. 指标

设 N 为创建任务时确认的用例总数，P 为 PASSED，F 为 FAILED：
- 通过率 = P / (P + F) × 100%。
- 执行完成率 = (P + F) / N × 100%。
- 处理进度 = 已得到终态的用例数 / N × 100%，与完成验证的比率分开展示。

例如 N=10、P=8、F=1、BLOCKED=1：通过率 88.9%，执行完成率 90%，处理进度 100%。
终态包括 PASSED、FAILED、BLOCKED、ERROR、CANCELLED、INTERRUPTED。
任务 COMPLETED 可能完成率不足 100%，必须展示各状态数量，不能只展示绿色“完成”。

P+F=0 时通过率为空并显示“暂无可判定结果”。
N=0 的任务不允许开始；指标函数仍需处理零分母，不返回 NaN/Infinity。
显示值统一由服务端四舍五入到一位小数；状态数量以整数为准，报告与页面不能各算一套。
