# M4 小阶段：有限恢复与提交不确定

状态：本机可控故障验证完成，完整 P0 未完成。
对应验收：D05、D08、D09。进程中断留待下一小阶段；Windows 实机继续延后。

## 问题与预期行为

当前定位错误主要受整条用例的总时限限制；点击指纹也不能覆盖按键、标签变化等情况。本轮由服务限制每阶段的定位恢复次数和恢复时间，保留最初错误。操作已经发出却没有可靠回执时，只读收集现场后结束为 ERROR，不盲目重放或继续后续业务步骤。

## 本次范围

- 默认每步骤/准备阶段/独立预期最多 2 次定位恢复，恢复累计活动时间最多 120 秒；暂停时间不消耗恢复预算。
- 定位失败后必须重新取快照再定位。动作发出前的定位失败可以恢复，发出后的异常按结果不确定处理。
- 点击、输入、选择和按键都经过服务端边界；保留原始失败、恢复记录、最后动作与只读现场。
- 真实模型与 MCP/Chrome 联调，注入一次定位故障、持续定位故障、实际提交后的回执丢失；检查实际调用和页面/目标服务计数。
- 故障注入只在验收脚本的宿主代码中，不开放 HTTP 或用户上传内容可启用的测试开关；不改原用例以消除失败。

## 验证与完成条件

先对独立预算与写操作状态做有意义的失败测试，再实现边界。真实故障验收保留所有工具与截图，明确故障注入和真实业务操作的区别；不得用测试替身冒充真实 Pi/MCP 接通。使用独立验收数据与共享浏览器锁，不修改用户环境或重启用户服务。

实际证据见 [有限恢复验证记录](../m4-recovery-verification.md)。恢复成功、次数耗尽、时间耗尽、回执丢失四场景均以真实模型/MCP/Chrome 验证，最终命令退出 0。首次命令收尾异常已保留，修复并发边界计时器后新建运行补验，不覆盖历史或强制退出掩盖清理。50 项测试、类型检查和 Web 构建通过。后续继续进程中断与数据清理边界；Windows 实机延后。
