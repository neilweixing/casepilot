## 目标与边界

本阶段接通已确认版本 → 选定环境 → UI 登录/前置准备 → 顺序执行 → 逐项预期和证据 → 页面结果。
用可控系统分别验证通过、明确失败、前置阻塞及后续继续；第二个任务必须被服务拒绝。
真实用户 xlsx 与系统仍待后续提供；不自动提交、推送，不自动启动/重启用户服务。

## 实现与验证

本轮引用定位修复对应 D07：旧证据显示 `f1e11` / `f1e9` 被传给 `document.querySelector`，导致反序位置验证超时。修复目标是兼容原样快照引用与唯一 CSS，保留只读脚本边界；缺目标、跨页/视口变化不生成可靠位置证据。沿用原始用例和 600 秒预算，新建反序任务，要求文字预期 PASSED、位置预期 FAILED 且有坐标记录。当前无活动任务，后端修改由已启动的 watch 自动加载，不手动重启服务。

1. 核对初稿，验证阶段禁止写操作，完成步骤须有本阶段成功操作证据。
2. 服务校验全部步骤、预期与证据关联，不接收空结果的 PASSED；明确失败不能被后续错误覆盖。
3. 账号通过服务端受控工具填写；递归脱敏后再存储或返回，检查引号/反斜杠等凭证。
4. 单任务占用与 M1 验收命令共享执行锁；异常进程未释放时不能接新任务。
5. 使用生成的工作簿、可控页面和真实模型，从 Web 启动任务；保存页面和运行证据。
6. 边界测试、类型检查与构建通过后，按实测结果开放入口并更新计划。
