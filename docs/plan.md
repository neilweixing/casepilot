## M0：本次交付

- 工程名字 CasePilot，独立目录。
- 根 README 和 AGENTS，需求/设计/执行/验收/决策文档。
- 三个 workspace 的元数据和预留目录，无业务实现。
- 无真实凭证的本地配置示例与脱敏用例样本。
- 无第三方依赖的文档/配置检查；M0 当时的锁文件不包含运行依赖，M1 已加入精确依赖。
- 不启动服务、不安装 Pi/MCP/浏览器、不连接被测系统、不提交或推送代码。

## M1：先证实最难的链路

具体任务见 [M1 任务卡](tasks/M1-agent-smoke.md)。
先核实可安装版本、模型工具/图像能力、官方 MCP 扩展注册和工具清单。
在可控页面验证一条用例及字段相对位置，不先做完整管理界面再发现执行链路不通。

完成标准：实际工具记录、截图、结构化结果能对应同一次执行，失败样本也能正确分类。
只完成这条链路不能对用户说“P0 已可用”。

2026-10-30 实施：精确依赖、最小 Fastify 页面、Pi/MCP 工具隔离、逐项结果与文件证据、终止清理已实现。
已用用户配置的模型完成正常 `PASSED` 与反序 `FAILED`，打开页面后终止为 `CANCELLED` 且进程释放；最终检查与运行编号见 [M1 验证记录](m1-verification.md)。
实际入口：`pnpm dev`（用户启动服务）、`pnpm smoke`、`pnpm smoke --variant=reversed`、`pnpm stop:check`；静态/边界检查为 `pnpm typecheck`、`pnpm test`、`pnpm check`。

## M3：建立实际任务工作流

环境表单、受限凭证存储、用户名密码登录与验证码适配。
一台本机一个活动执行任务；前置检查与准备、每条上下文独立、结果逐条持久化。
Web 页面从任务表单创建执行，不依赖对话中的隐含状态。
无可用模型/环境时显示未配置，不用假数据冒充真实连接。

后续完成 [普通图片验证码任务](tasks/M3-image-captcha.md)：只截取验证码区域，确认图片实际发送给模型后提交；每图一次，服务限制识别/提交/刷新次数，导航与换证据 ID 不能重用已提交图像。正常、首次失效后刷新、持续拒绝达到上限、不可读停止均有真实模型/MCP/Chrome 证据，补充保护后再新建刷新回归。8 次可读识别正确 8/8；不可读观察 3 次、0 提交；两种故障整批暂停，后续业务未开始。62 项测试和类型检查通过；五份报告共 301 项证据、15 张截图，313 个文本文件脱敏及 10 张去重图像检查通过，工具和锁释放。未修改 Web、未重复构建；实际命令、样本成功率与限制见 [图片验证码记录](m3-image-captcha-verification.md)。

## 每次任务的退出要求

- 只标记已经实现且验证过的条目。
- 修改了需求或执行规则时同步文档与验收项。
- 报告实际检查与结果，没有运行的检查明确写未运行。
- 需要服务重启时交给用户操作，不自行重启。
